# backsteros-mobile

Expo SDK 55 + Expo Router product client.

**Status:** Local-shell auth (no sign-in), Inbox + Journal + Tasks + Projects with
PowerSync and offline status edits. See [ARCHITECTURE.md](./ARCHITECTURE.md)
for layering and conventions.

Tab chrome is two floating blurred pills (`components/floating-tab-bar.tsx` +
`expo-blur`, hosted in `FullWindowOverlay` on iOS): main nav Inbox → Journal →
Calendar → Tasks → More, and a separate compose pill (desktop create icon).

Re-run `prebuild` and rebuild the dev client after native dependency changes
(`expo-libghostty`, `@shopify/react-native-skia`, OP-SQLite, etc.).

## SQLite adapters

| Environment | Adapter |
| --- | --- |
| Expo Go (`executionEnvironment === "storeClient"`) | `@powersync/adapter-sql-js` (JS only — dev/recovery) |
| Dev client / production (`expo run:*`, EAS) | `@powersync/op-sqlite` + `@op-engineering/op-sqlite` (New Arch) |

```bash
# Expo Go (SQL.js) — limited; prefer native for foundation work
pnpm --filter @backsteros/mobile dev

# Native SQLite (requires Xcode once)
pnpm --filter @backsteros/mobile prebuild
pnpm --filter @backsteros/mobile ios          # simulator
pnpm --filter @backsteros/mobile build        # physical device (= ios:device)
```

`ios/` and `android/` are generated by `prebuild` (gitignored).

## Develop

```bash
cp mobile/.env.example mobile/.env
# Set EXPO_PUBLIC_API_URL (LAN / Tailscale for devices)
pnpm install
pnpm --filter @backsteros/mobile ios
```

Requires a running API. PowerSync (`GET /api/v1/powersync/token`) enables local
SQLite for Tier A/B lists and metadata on **local-core only**.

No demo fixtures — the app uses local-shell auth against your workspace.

### Cloud REST fallback

When local-core is offline, set `EXPO_PUBLIC_CLOUD_API_URL` (e.g. your tailnet
cloud-core URL). REST calls use `activeApiUrl` from `lib/api-url-context.tsx`.
PowerSync still targets local-core; cached SQLite continues to serve offline reads.

### iPad codebase agent TUI

On **iPad**, codebase project tasks use a stacked detail | agent terminal layout.
The agent pane is full-bleed (no nav header); Start/Stop floats over the TUI.
Ghostty’s soft-keyboard accessory bar is disabled (hardware keyboard assumed).

Rendering is **Ghostty (Metal)** via `expo-libghostty` — not WebView xterm.
Transport is a **native WebSocket** to the laptop `pnpm --filter @backsteros/desktop pty` sidecar over Tailscale.

1. Core: set `AGENT_PTY_PUBLIC_URL` and `AGENT_PTY_AUTH_TOKEN`
2. Desktop: `PTY_HOST=0.0.0.0 PTY_AUTH_TOKEN=<same> pnpm --filter @backsteros/desktop pty`
3. Rebuild after `expo-libghostty` changes:

```bash
pnpm --filter @backsteros/mobile prebuild
pnpm --filter @backsteros/mobile ios:device
```

iPhone agent TUI is deferred; phone keeps the single-column task screen.

## Foundation checklist — Journal on iOS Simulator

1. **API** — local `core/server` on `http://127.0.0.1:8788` (or Tailscale) with local-shell auth.
2. **Env** — `EXPO_PUBLIC_API_URL`.
3. **Seed** — at least one journal document.
4. **Native build** (not Expo Go):

   ```bash
   pnpm --filter @backsteros/mobile prebuild
   pnpm --filter @backsteros/mobile ios
   ```

5. **Verify** — open app → **Journal** lists entry titles.

Physical device: point `EXPO_PUBLIC_API_URL` at Tailscale MagicDNS, not `127.0.0.1`.

`pnpm start` / `pnpm ios:device` set `REACT_NATIVE_PACKAGER_HOSTNAME` from the
API host so the Dev Client opens Metro over Tailscale.
