# backsteros-mobile

Expo SDK 54 + Expo Router product client (Phase 4).

**Status:** Clerk sign-in, Inbox + Journal + Tasks + Projects with PowerSync and
offline status edits. Document body open-on-demand is next (journal tab is a title list for now).

Tab chrome is two floating blurred pills (`components/floating-tab-bar.tsx` +
`expo-blur`, hosted in `FullWindowOverlay` on iOS): main nav Inbox → Journal →
Tasks → Projects, and a separate compose pill (desktop create icon).

## SQLite adapters

| Environment | Adapter |
| --- | --- |
| Expo Go (`executionEnvironment === "storeClient"`) | `@powersync/adapter-sql-js` (JS only) |
| Dev client / production (`expo run:*`, EAS) | `@powersync/op-sqlite` + `@op-engineering/op-sqlite` (New Arch) |

```bash
# Expo Go (SQL.js) — limited; prefer native for foundation work
pnpm --filter @backsteros/mobile start

# Native SQLite (requires Xcode once)
pnpm --filter @backsteros/mobile prebuild
pnpm --filter @backsteros/mobile ios
```

`ios/` and `android/` are generated by `prebuild` (gitignored). Re-run `prebuild`
after adding Expo native modules (e.g. `expo-web-browser`).

## Develop

```bash
cp backsteros-mobile/.env.example backsteros-mobile/.env
# Set EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY (+ LAN API URL for devices)
pnpm install
pnpm --filter @backsteros/mobile ios
```

Requires a running API. PowerSync (`GET /api/v1/powersync/token`) enables local
SQLite for Tier A/B lists and metadata.

No demo fixtures when signed out or when the Clerk key is missing.

### iPad codebase agent TUI

On **iPad**, codebase project tasks use a stacked detail | agent terminal layout.
The agent pane is full-bleed (no nav header); Start/Stop floats over the TUI.
Ghostty’s soft-keyboard accessory bar is disabled (hardware keyboard assumed) —
requires a native rebuild after install (`pnpm ios:device`).

Rendering is **Ghostty (Metal)** via `expo-libghostty` — not a WebView xterm.
Transport is a **native WebSocket** to the laptop `pnpm pty` sidecar over Tailscale;
rendering is **Ghostty (Metal)** via `expo-libghostty` — not a WebView xterm.

1. Core: set `AGENT_PTY_PUBLIC_URL` (e.g. `http://macbook.tailnet.ts.net:3101`) and `AGENT_PTY_AUTH_TOKEN`
2. Desktop: `PTY_HOST=0.0.0.0 PTY_AUTH_TOKEN=<same> pnpm pty`
3. After adding/updating `expo-libghostty`, rebuild the native app:

```bash
pnpm --filter @backsteros/mobile prebuild
pnpm --filter @backsteros/mobile ios:device
```

Metro-only reloads are not enough — Ghostty is a native module.

iPhone agent TUI is deferred; phone keeps the single-column task screen.

## Production / release

- **EAS** — `eas.json` profiles: `development`, `preview`, `production`. Run from
  this package with the EAS CLI (`eas build --profile preview`).
- **Crash reporting** — optional. Set `EXPO_PUBLIC_SENTRY_DSN`, install
  `@sentry/react-native`, add the Expo Sentry plugin, then re-run `prebuild`.
  Without a DSN the app no-ops (see `lib/sentry.ts` + root `AppErrorBoundary`).
- **Checks** — `pnpm --filter @backsteros/mobile typecheck` and
  `pnpm --filter @backsteros/mobile test`.

## Foundation checklist — Journal on iOS Simulator

1. **API** — production `https://service.backsteros.com` or local
   `backsteros-api` on `http://127.0.0.1:8787` with Clerk and a workspace.
2. **Env** — `backsteros-mobile/.env` with `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY` and
   `EXPO_PUBLIC_API_URL` pointing at that API.
3. **Seed** — at least one journal document (create via web/desktop/API).
4. **Native build** (not Expo Go):

   ```bash
   pnpm --filter @backsteros/mobile prebuild
   pnpm --filter @backsteros/mobile ios
   ```

5. **Verify** — Simulator opens → sign in → **Journal** lists entry titles.
   Tasks tab covers due-date filters (Today / Tomorrow / …).

Physical device: point `EXPO_PUBLIC_API_URL` at your Tailscale MagicDNS host
(or LAN IP), not `127.0.0.1`.

`pnpm start` / `pnpm ios:device` set `REACT_NATIVE_PACKAGER_HOSTNAME` from that
API host so the Expo Dev Client opens Metro over Tailscale instead of asking
you to **Enter URL manually** every launch. Override with
`REACT_NATIVE_PACKAGER_HOSTNAME` in `.env` if needed. Keep Metro running
(`pnpm start:dev-client`) before opening the app on the iPad.

### Xcode 26 note

Apple Clang in Xcode 26+ fails to compile React Native’s bundled `fmt` 11.x
(`FMT_STRING` / consteval). A config plugin
([`plugins/with-fmt-xcode-fix.js`](plugins/with-fmt-xcode-fix.js)) patches
`fmt/base.h` during `prebuild` / `pod install` (RN #55601). Remove once RN ships
fmt ≥ 12.1.
